# CHANGELOG.md

Meaningful changes only — not every commit. This is what lets an agent (or
you, weeks later) understand how the project evolved without re-reading
the whole git log.

Format, newest first:

```
## [Unreleased]
### Added
### Changed
### Fixed
### Security

## YYYY-MM-DD
### Added
- [what shipped]
### Changed
- [what changed and why, one line — link to DECISIONS.md for the full
  reasoning]
### Fixed
- [bug fixed]
### Security
- [security-relevant change — always call these out separately]
```
